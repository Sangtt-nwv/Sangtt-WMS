## Decision: `.agents/skills/` (Codex) is based on `current`, not `standalone`

Before merging, every same-named skill file was diffed and separately grepped for the
phrase pair `"DO NOT STOP OR ABORT"` / `"Fallback gracefully to directly"` — the language
that authorizes an agent to silently hand-write new AOT XML instead of using `d365fo
generate`/the Bridge/the wizard when the CLI is "not available", with no requirement to ask
the user first. This is the exact policy that led to a real ~2-day production debugging
incident (a hand-authored `AxDataEntityView` compiled cleanly but never routed via OData —
see `data-entity-odata-404-troubleshooting`).

Result:

| Source | Skill files with the unconditional-fallback banner | Verdict |

| `standalone` `.agents/skills/` (32 files) | **17** | Not merged in wholesale. |

`standalone`'s copies had later file-modification timestamps than `current`'s in several
cases — timestamp alone was deliberately *not* used as a proxy for "more correct", since in
this instance the newer file was the regression. Where `standalone` had a non-dangerous

## 2026-09-18 — second regression of the same policy, and the structural fix

The remediation recorded above did not hold. A full audit on 2026-09-18 found the
unconditional-fallback banner alive in **65 files**, and found that the guard written to
prevent exactly that was both failing and looking in the wrong places.

### What had gone wrong

| Finding | Evidence |
|---|---|
| Banner live in 65 files | `.agents/` 8, `.github/` 29, `.vscode/` 28. `.claude/` was clean. |
| `check-skill-sync.ps1` swept only `.agents` + `.claude` | 9 of 65 infected files were in scope. The other 56 were invisible to it. |
| The script was failing and nobody ran it | `exit 1`, 15 issues, no CI called it. |
| The earlier banner removal destroyed content | `git diff --stat` on `.agents`: 258 insertions, **1,986 deletions** across 32 files. Rich skills were replaced with ~15-line stubs rather than having one line removed. `coc-extension-authoring` went 105 → 15 lines, losing the `prepare change --grounding-token` workflow. |
| `.claude/` was never in version control | `.gitignore` blocks `/*` and whitelists by name; `.claude/` was not on the list. `git ls-files .claude/skills` returned 0. `CLAUDE.md`, `.mcp.json` and this file were also ignored; `AGENTS.md`, `README.md` and both `tools/*.ps1` were never `git add`-ed. A fresh clone produced a repo with no Claude configuration at all — including no bootstrap script to rebuild it. |
| 5 `.claude` skills were empty directories | `data-upgrade-and-migration`, `error-handling-and-logging`, `financial-dimensions-patterns`, `ledger-posting-patterns`, `unit-testing-patterns` had no `SKILL.md`, so Claude Code never loaded them. Their `.agents` counterparts had 124–180 lines of real content — and all five carried the banner, which is why they were skipped when `.claude` was cleaned. |
| The 6 subagents did not exist for Claude Code | `AGENTS.md` and `CLAUDE.md` both instruct the use of `reviewer`, `tech-lead`, `xpp-coder`, `db-query`, `integration`, `security-auditor`. There was no `.claude/agents/`; they existed only as `.codex/*.toml` and `.github/*.agent.md`. |
| 7 copies per topic, 5 distinct bodies | For `coc-extension-authoring`: `.agents` 1,055 B, `.claude` 7,819 B, `.github/instructions` and `.github/skills/*.instructions.md` 5,128 B (identical to each other), `.github/skills/*/SKILL.md` 4,671 B, `.github/skills/d365fo-cli/references` 7,462 B, plus `.vscode/skills`. |

### The root cause

Every one of these is the same failure: **the rules lived only in prose, and the copies had
no single owner.** A policy written in 65 places drifts in 65 places. A guard that is not
run by CI is documentation. A source of truth that is not in Git is a working copy.

### What was changed

- `tools/strip-fallback-banner.ps1` replaced the banner in all 65 files with one that
  matches `AGENTS.md` → "Metadata And AOT Safety": stop and report the missing prerequisite.
  One line per file — the earlier stub-swap approach was not repeated.
- `check-skill-sync.ps1` now sweeps `.agents`, `.claude`, `.github`, `.vscode` and `.codex`.
- `.claude/skills/` is now the **single source of truth**; `tools/sync-agent-skills.ps1`
  generates the Codex and Copilot mirrors from it and `-Check` fails CI on drift.
  Verified against official docs: Codex reads `.agents/skills`, Copilot reads
  `.github/skills`, and **`.vscode/skills/` is not a location any client reads** — it was
  removed. `.github/instructions/` (21 files) and `.github/skills/*.instructions.md`
  (19 files) were superseded and removed; `copilot-canon.md`'s 19 pointers to them were
  repointed at the skills that replaced them.
- `.claude/` is in `.gitignore`'s whitelist; per-developer state stays local.
- The 5 empty skills were filled (confirmed live: they now load).
- `.claude/agents/` now holds the 6 subagents the instructions promised.
- Three rules became Claude Code hooks instead of prose — see `AGENTS.md` → "Enforcement".
  The AOT-XML block was tested against four cases: new object blocked, existing object
  allowed, non-`Metadata/` path allowed, authorized override allowed.

### What is still true and worth keeping in mind

The `.claude` corpus was chosen as the source because it was the only mirror with **zero**
infected files and the richest content. That was luck, not design — nothing protected it.
What protects it now is that it is tracked, generated from, and guarded by two scripts that
CI runs. If a future session finds this section out of date, the guards are the first thing
to check.
